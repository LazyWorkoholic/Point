## Purpose

## Build

Scope each piece to the listed failures. **Do not build all of it by default.**

Location: `backend\managers\memory.py` (exists, empty) plus
`backend\database\memory_repository.py` (new), mirroring the existing
`session_repository.py` pattern — pure SQL, zero business rules.

### Fact extraction → proposals
- After a task completes, one cheap call extracts candidate facts.
- Writes `memory_records` with `status=pending`, `source=auto_extractor`,
  `agent_id`, `origin_session_id`, `origin_task_id`.
- **At most 2–3 per session**, enforced by a counter on the session, never by
  prompt instruction.
- Emits `memory.proposed` so the UI can badge it. **Never blocks a task.**

### Review operations
`accept(id)`, `reject(id)`, `edit(id, content)`, `bind(id, scope, scope_id)`,
`unbind(...)`, `forget(id)`.

Accepting sets `status=accepted`. A card save writes `accepted` +
`source=user_card` directly — the click *is* the approval, not a second proposal.

`forget(id)` deletes the record **and all its scope bindings**. `unbind` removes
one binding and leaves the record.

### Search
- SQLite **FTS5** over `content` plus tags.
- Tags generated by the same extraction call (3–5 per record). This is what
  closes most of the semantic gap for zero extra cost.
- `search(query, scopes, limit)` reads `status='accepted'` **only**. One WHERE
  clause, and it is the guardrail against memory poisoning.
- Precedence on conflict: **session > project > global**.
- Deduplicate by `memory_id` — a record bound to two scopes is returned once.
- Behind the `MemoryService` interface from B8, so embeddings later touch one file.

### Retrieval mode
- **Manual by default**: the user attaches a memory, producing a
  `context_attachments` row.
- `retrieval.automatic = false` in config. When true, B8 calls `search` with the
  turn's text and injects top-k under a token sub-budget. **Ship it off.**

### Summarization (only if a listed failure demands it)
- Triggered by session length **in tokens**, not message count.
- The summary is a `memory_record` bound to the session, so it flows through the
  same storage and the same review path.
- **Original messages are never deleted** — the summary substitutes for them in
  context only.

### Auto-accept escape hatch
`memory.auto_accept = false`, per project. When true, extractor output lands as
`accepted`. It exists so review can be switched off deliberately rather than by
mashing "accept all".

Add `cli.py memory list|accept|reject|edit|bind|unbind|forget|search`.

- Introduce a `writes_global` capability for any agent.

**Expect:** found via its tags.
**Fails if:** only exact-word queries hit — the tags are not doing their job.

```powershell

```
**Expect:** the pending record is **not** returned.

```powershell

uv run python cli.py memory bind <id> --scope session --id <session-id>
uv run python cli.py memory search "<query>" --scopes session,project
```
**Expect:** returned once, not twice.

```powershell
# 5. forget

sqlite3 "$env:LOCALAPPDATA\Point\runtime.db" "select count(*) from memory_scopes where memory_id='<id>';"

```
**Expect:** `0` and `0`.


**Expect:** with `retrieval.automatic=false`, no memory section. Flip it to true,
repeat, and a memory section appears with a real token cost.
